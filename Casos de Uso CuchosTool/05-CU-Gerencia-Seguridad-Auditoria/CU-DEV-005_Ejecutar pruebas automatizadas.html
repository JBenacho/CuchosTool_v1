CU-DEV-005 - Ejecutar pruebas automatizadas

Proyecto: CuchosTool.com | Baseline: SRS v5.0 / ARQ v6.0 / BL v5.0
Módulo: DevOps / Testing / DOM-DEV | Fecha: 02/09/2026
Responsable: Nicola | Rol: Arquitecto & Dirección Técnica
1. Información General
ID / Código: CU-DEV-005
Trazabilidad: DEV-05, RNF-003, BL-010, BR-02
Nombre: Ejecutar pruebas automatizadas
Objetivo: Orquestar y ejecutar suites de pruebas automatizadas (unitarias, integración y E2E) dentro del pipeline CI.
Actor Principal: Test Runner (Jest / Cypress / Newman)
Actores Sec.: CI Pipeline, Cloud SQL Test, Test Data Manager
Tipo / Prioridad: DevOps / Testing Prioridad Esencial
Estado: Aprobado / Aseguramiento de Calidad (Baseline v6.0)
Disparador: Ejecución de la etapa de testing dentro del flujo de integración continua.
Precondiciones: 1. Artefactos compilados y entorno de prueba efímero listo.
Resultado: Test Suites Passed (Status Check Success) o fallo con reportes JUnit.
2. Diagrama de Casos de Uso (UML)
3. Descripción y Alcance

Propósito: Validar la conformidad funcional mediante pruebas automáticas para evitar regresiones.

Acceso: Ejecución automatizada en pipeline CI.

Frontera DevOps: Aseguramiento de calidad; no despliega a producción.

4. Reglas de Negocio (RN)
  • BR-02 / RN-DEV-010: Default Deny ante fallos en tests unitarios o integración.
  • RN-DEV-011: Ejecución obligatoria de Smoke Tests previo a habilitar staging.
  • RN-OPS-012: Duración máxima de suite p99 ≤ TBD min.
5. Flujo Principal (Camino Feliz)
1
Pipeline CI inicia etapa de pruebas tras compilación exitosa.
2
Aprovisionamiento de base de datos efímera de test con fixtures iniciales.
3
Ejecución concurrente de pruebas unitarias (backend / frontend).
4
Ejecución de pruebas de integración y API sobre contenedores locales.
5
Recopilación de resultados en formato JUnit XML y métricas de cobertura.
6
Validación de umbrales mínimos (100% de aserciones críticas pasadas).
7
Emisión de estatus check exitoso hacia Git Server.

  • TestExecutionResultDTO: suiteName, passed, failed, duration.
  • JUnitReportXML: Reporte estructurado para CI.
  • TestFixtures: Datos iniciales mock para pruebas.
  • X-Correlation-ID: Trazabilidad distribuida.
10. Criterios de Aceptación (DoD)
  • ✓ Suites de pruebas automatizadas operando en CI.
  • ✓ Reportes JUnit y cobertura generados.
  • ✓ Cero tolerancia a tests fallidos (Default Deny).
  • ✓ Latencia p99 verificada (BL-010).
