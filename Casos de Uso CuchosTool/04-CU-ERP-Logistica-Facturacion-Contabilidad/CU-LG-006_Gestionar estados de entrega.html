ID / Código: CU-LG-006 [Trazabilidad: RF-LG-006, RNF-LG-001, BL-LG-06] Nombre: Gestionar estados de entrega Objetivo: Actualizar y monitorear el ciclo de vida y los estados de entrega de las guías y despachos logísticos (en tránsito, entregado, devuelto). Actor Principal: ADMINISTRADOR_LOGISTICA / TRANSPORTISTA (Autenticado / JWT interno) Actores Sec.: Logistics Service (DOM-LG-01), Cloud SQL PostgreSQL, Cloud Pub/Sub Tipo / Prioridad: Transaccional ERP / Trazabilidad Prioridad Alta / Esencial Estado / Alcance: Aprobado / Backoffice ERP & Operación de Campo (Actualización de estados bajo RBAC) Disparador: El transportista o operador logístico registra una novedad o confirma la entrega final de una guía en destino. 2. Usuario autenticado con rol autorizado. Postcondiciones: Estado de entrega actualizado en erp_shipping_guides, historial de checkpoints ampliado y evento emitido. Resultado Exitoso: HTTP 200 OK / 201 Created con DeliveryStatusDTO actualizado y trazabilidad reflejada en tiempo real.
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Permite registrar actualizaciones de estado y novedades en la entrega de guías logísticas.

Frontera ERP y Aislamientio: Módulo logístico interno. Estrictamente aislado del E-Commerce público y del kárdex de inventario.

4. REGLAS DE NEGOCIO (RN)
  • RN-LG-01 (Transición Secuencial): Los estados de entrega deben seguir el flujo lógico establecido (CREATED → IN_TRANSIT → DELIVERED / RETURNED).
  • RN-LG-02 (Inmutabilidad de Entregados): Una guía marcada con estado DELIVERED o RETURNED no puede retroceder a estados intermedios.
  • RN-LG-03 (Propagación Asíncrona): Todo cambio de estado crítico debe emitir un evento a Cloud Pub/Sub para notificar al portal de clientes.
  • RN-LG-04 (Default Deny): Acceso restringido exclusivamente a roles operativos autorizados (ADMINISTRADOR_LOGISTICA, TRANSPORTISTA).
  • RN-LG-05 (SLO Rendimiento): Tiempo de procesamiento ≤ 250 ms (p95) en Google Cloud Run.
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Captura de Estado: El operador o transportista envía PATCH /api/v1/erp/logistics/guides/:id/status indicando el nuevo estado y ubicación.
  • 2 Validación de Acceso: El API Gateway y middleware RBAC verifican el token JWT corporativo y el rol autorizado.
  • 3 Verificación de Transición: Logistics Service valida en Cloud SQL que la transición de estado sea lógicamente permitida.
  • 4 Persistencia Atómica: Se actualiza la guía en la tabla erp_shipping_guides y se añade un nuevo registro al historial de checkpoints.
  • 5 Publicación de Evento: Se emite el evento asíncrono ShippingGuideStatusUpdated a Cloud Pub/Sub.
  • 6 Confirmación: El servicio responde HTTP 200 OK con ShippingGuideDTO actualizado.
  • 7 Actualización Omnicanal: El nuevo estado se refleja de inmediato para la consulta pública de tracking de los clientes.

8. FLUJOS ALTERNATIVOS / EXCEPCIONES
Código Situación Comportamiento del Sistema
FA-01 Transición de estado inválida HTTP 422 Unprocessable Entity impidiendo retroceder o alterar el flujo secuencial de entrega.
FA-02 Token ausente o rol no autorizado HTTP 403 Forbidden bajo la política de seguridad Default Deny.
FA-03 Guía inexistente en actualización HTTP 404 Not Found al intentar actualizar una guía no registrada en el ERP.
FA-04 Fallo en Cloud SQL HTTP 500. Notificación en Cloud Logging y mensaje amigable de reintento.
FA-05 Fallo en Cloud Pub/Sub El estado se actualiza localmente y el evento se almacena en tabla Outbox para reintento asíncrono.

  • Visibilidad: Estrictamente interno para actualización; público para consulta.
