CU-EC-002 - Buscar productos

Proyecto: CuchosTool / CuchosTool.com
Versión: 5.0 (SRS v5.0 / ARQ v6.0 / BL v5.0)
Módulo: E-Commerce / Catálogo (DOM-01)
Fecha: 01/09/2026
Responsable: Nicola (Gerente del Proyecto)
Rol: Arquitecto & Dirección Técnica
1. INFORMACIÓN GENERAL
ID / Código: CU-EC-002 [Trazabilidad: RF-EC-001, RF-EC-002, US-002, CMP-001..003] Nombre: Buscar productos Objetivo: Permitir a visitantes o clientes localizar herramientas y artículos activos mediante palabras clave, SKU, nombre comercial o etiquetas. Actor Principal: Cliente E-Commerce / Visitante (Público) Actores Sec.: Product Service (DOM-01), Cloud CDN / Storage, Cloud SQL Tipo / Prioridad: Búsqueda Pública Prioridad Alta / Esencial Estado / Alcance: Aprobado / E-Commerce Abierto (Sin token JWT ni registro) Disparador: El visitante introduce un término en la barra de búsqueda o ejecuta consulta HTTP con parámetro q. Precondiciones: 1. Servicios operativos en Cloud Run.
2. Catálogo indexado con productos activos (isActive = true). Postcondiciones: N/A (Operación idempotente de solo lectura; no muta inventario ni transacciones). Resultado Exitoso: HTTP 200 OK con colección de coincidencias ordenadas por relevancia y paginadas.
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Mecanismo de búsqueda textual indexada sobre el catálogo público de herramientas para agilizar el hallazgo de productos.

Frontera ERP y Desacoplamiento: La búsqueda se ejecuta sobre réplicas o esquemas de catálogo (catalog.products), garantizando aislamiento absoluto frente a las bases de datos contables o transaccionales del ERP.

4. REGLAS DE NEGOCIO (RN)
  • RN-EC-001: Búsqueda pública abierta; no exige registro ni autenticación.
  • RN-CAT-01: Filtro obligatorio de disponibilidad comercial: isActive = true.
  • RN-CAT-02: Endpoint expuesto sin middleware de sesión (GET /products/search).
  • RN-CAT-04: Resultados paginados por defecto (page = 1, limit = 20).
  • RN-CAT-05: Latencia de respuesta: ≤ 100 ms (p95) en cache/CDN; ≤ 300 ms en Cloud Run.
  • RN-SEC-01: Sanitización estricta del query (prevención de SQLi y XSS reflejado).
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Ingreso de Criterio: El visitante introduce texto en la caja de búsqueda y presiona Enter o interactúa con el buscador web.
  • 2 Envío de Petición HTTP: El Front/BFF emite GET /products/search?q={query}&page=1&limit=20 sin requerir cabecera Bearer Token.
  • 3 Sanitización y Validación: El enrutador verifica que la longitud sea ≥ 2 caracteres y escapa caracteres de escape o control.
  • 4 Ejecución de Búsqueda (DOM-01): Product Service consulta en Cloud SQL PostgreSQL aplicando índices en name, description, sku y tags con isActive = true.
  • 5 Asociación de Assets: Se vinculan las URLs cacheadas en Cloud Storage/Cloud CDN para miniaturas de herramientas encontradas.
  • 6 Métricas de Búsqueda: Se emite registro estructurado JSON a Cloud Logging con duración, query sanitizado y total de coincidencias.
  • 7 Renderizado de Coincidencias: La interfaz despliega la cuadrícula de resultados con tarjetas de producto, precios en COP y paginador.
6. DIAGRAMA DE SECUENCIA (UML)
7. DIAGRAMA DE ACTIVIDADES (UML)
8. FLUJOS ALTERNATIVOS / EXCEPCIONES
Código Situación Comportamiento del Sistema
FA-01 Búsqueda sin coincidencias HTTP 200 OK con lista vacía [] y visualización de productos sugeridos.
FA-02 Longitud insuficiente (< 2) HTTP 400 Bad Request. Alerta al usuario solicitando al menos 2 caracteres.
FA-03 Inyección / caracteres no válidos Sanitización y escape automático; la consulta se procesa como texto literal seguro.
FA-04 Fallo en Cloud SQL (DB) HTTP 500. Notificación en Cloud Logging y mensaje visual amigable para reintentar.
FA-05 Pico de consultas concurrentes Protección mediante Cloud Armor / Rate Limiting per-IP sin degradar el backend.
9. DATOS UTILIZADOS
  • Parámetros de Entrada: q (string de búsqueda), page, limit, sort.
  • Entidad Producto: id (PROD-XXXX), sku, name, description, brand, category, basePrice, tags, isActive.
  • Mapeo Multimedia: imageUrl (Cloud Storage / CDN).
  • Moneda Comercial: COP (Pesos Colombianos).
  • Respuesta de Paginación: totalHits, totalPages, currentPage.
10. CRITERIOS DE ACEPTACIÓN (DOD)
  • ✓ Acceso 100% público sin requerir token JWT (US-002).
  • ✓ Filtro estricto de productos con isActive = true.
  • ✓ Aislamiento total de las bases de datos transaccionales del ERP.
  • ✓ Sanitización obligatoria de entradas contra inyección SQL.
  • ✓ Emisión de logs estructurados JSON a Cloud Logging.
  • ✓ Latencia de respuesta: ≤ 300 ms (p95) en Cloud Run.
11. INTEGRACIONES
Servicio Protocolo Propósito
Search Router HTTP REST Exposición del endpoint público /products/search.
Product Service TypeScript/Drizzle Lógica de búsqueda textual, scoring de relevancia y paginación.
Cloud SQL (DB) PostgreSQL Índices Full-Text/Trigram en esquema catalog sin tocar ERP.
Cloud Storage / CDN HTTPS Resolución y distribución optimizada de imágenes y assets.

CU-EC-001 - Consultar catálogo

Proyecto: CuchosTool / CuchosTool.com
Versión: 5.0 (SRS v5.0 / ARQ v6.0 / BL v5.0)
Módulo: E-Commerce / Catálogo (DOM-01)
Fecha: 01/09/2026
Responsable: Nicola (Gerente del Proyecto)
Rol: Arquitecto & Dirección Técnica
1. INFORMACIÓN GENERAL
ID / Código: CU-EC-001 [Trazabilidad: RF-EC-001, BL-033, US-001] Nombre: Consultar catálogo Objetivo: Permitir a cualquier visitante o cliente explorar de manera abierta el catálogo general de herramientas y productos activos disponibles. Actor Principal: Cliente E-Commerce / Visitante (Público) Actores Sec.: Product Service (DOM-01), Cloud CDN / Storage, Cloud SQL Tipo / Prioridad: Consulta Pública Prioridad Alta / Esencial Estado / Alcance: Aprobado / E-Commerce Abierto (Sin autenticación obligatoria) Disparador: El visitante ingresa a la URL principal o sección de productos o catálogo. Precondiciones: 1. Sitio web y servicios en Cloud Run operativos.
2. Catálogo publicado con productos activos (isActive = true). Postcondiciones: N/A (Operación de solo lectura; no altera BD ni reserva existencias). Resultado Exitoso: Respuesta 200 OK con grid de productos, categorías, imágenes y precios.
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Garantiza la navegación abierta del catálogo comercial bajo el estándar marketplace (Mercado Libre / Amazon).

Principio de Exploración Pública: No requiere token JWT ni registro previo. Desacoplamiento total: consume el dominio de catálogo (DOM-01) sin realizar consultas a la base transaccional del ERP.

4. REGLAS DE NEGOCIO (RN)
  • RN-CAT-01: Filtro estricto por isActive = true en el catálogo comercial.
  • RN-CAT-02: Endpoint público sin middlewares de autenticación (GET /products, GET /catalog).
  • RN-CAT-03: Precios base en Pesos Colombianos (COP) según la lista vigente del canal.
  • RN-CAT-04: Entrega de estructura paginada para optimizar ancho de banda.
  • RN-CAT-05: Latencia objetivo de consulta: ≤ 100 ms (p95) en CDN; ≤ 300 ms (p95) estándar.
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Solicitud de Catálogo: El visitante o cliente accede a la vista principal o envía petición HTTP GET /products (o /catalog).
  • 2 Enrutamiento Público (BFF): El enrutador recibe la solicitud sin interceptar con tokens de autenticación (cumplimiento BL-033).
  • 3 Consulta a Base de Datos (DOM-01): El Product Service ejecuta consulta a Cloud SQL (PostgreSQL) filtrando productos donde isActive = true.
  • 4 Carga de Referencias Multimedia: Se asocian las URLs públicas cacheadas en Google Cloud Storage / Cloud CDN para imágenes de herramientas.
  • 5 Consolidación de Payload: El sistema estructura la respuesta en formato JSON con la colección de productos, categorías, marcas y precios.
  • 6 Registro de Observabilidad: Se emite log estructurado JSON a Cloud Logging con métricas de duración.
  • 7 Presentación en UI: La interfaz renderiza el grid responsivo con tarjetas de producto y opciones de exploración.
6. DIAGRAMA DE SECUENCIA (UML)
7. DIAGRAMA DE ACTIVIDADES (UML)
8. FLUJOS ALTERNATIVOS / EXCEPCIONES
Código Situación Comportamiento del Sistema
FA-01 Sin productos activos HTTP 200 OK. Retorna array vacío [] y mensaje visual de inventario en actualización.
FA-02 Fallo en Cloud SQL (DB) HTTP 500 Internal Error. Registro en Cloud Logging y mensaje amigable de reintento.
FA-03 Fallo en Cloud CDN Carga de imagen placeholder por defecto sin degradar la visualización del producto.
FA-04 Acceso por alias /catalog HTTP 200 OK. Enrutador procesa la consulta con total equivalencia a /products.
FA-05 Intento de reserva anónima Intercepción y redirección a Login/Registro (CU-EC-013/014) preservando el producto.
9. DATOS UTILIZADOS
  • Entidad Producto: id (PROD-XXXX), sku, name, description, category, brand, basePrice, isActive.
  • Atributos de Presentación: imageUrl, tags, badges.
  • Moneda / Canal: COP ($ Pesos Colombianos).
  • Paginación: page, limit, total.
  • Filtros de Búsqueda: category, brand.
10. CRITERIOS DE ACEPTACIÓN (DOD)
  • ✓ Acceso público garantizado sin requerir token (BL-033).
  • ✓ Filtra estrictamente por productos activos (isActive = true).
  • ✓ Desacoplamiento total de la base de datos del ERP.
  • ✓ Soporta alias dual en enrutador (/products y /catalog).
  • ✓ Emisión de logs estructurados JSON a Cloud Logging.
  • ✓ Latencia de respuesta: ≤ 300 ms en Cloud Run.

Servicio Protocolo Propósito
Catalog Router HTTP REST Exposición de endpoints públicos /products y /catalog.
Product Service TypeScript / ORM Lógica de negocio y consultas de catálogo comercial.
Cloud SQL (DB) PostgreSQL Persistencia y recuperación de productos en esquema catalog.
Cloud Storage / CDN HTTPS Entrega optimizada de imágenes y assets estáticos.
