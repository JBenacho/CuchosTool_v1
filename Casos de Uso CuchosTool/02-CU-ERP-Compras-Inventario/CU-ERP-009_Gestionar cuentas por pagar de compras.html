1. INFORMACIÓN GENERAL
ID / Código: CU-ERP-009 [Trazabilidad: RF-FIN-001, US-121, BR-02, BR-07] Nombre: Gestionar cuentas por pagar de compras Objetivo: Causar contablemente las obligaciones financieras con proveedores a partir de órdenes de compra recibidas y facturas electrónicas, gestionando vencimientos y pagos. Actor Principal: CONTADOR (Autenticado / JWT interno) Actores Sec.: Finance Service (DOM-ERP-02), Cloud SQL PostgreSQL, Cloud Logging Tipo / Prioridad: Transaccional Financiero Prioridad Alta / Esencial Estado / Alcance: Aprobado / ERP Backoffice (Causación y tesorería bajo RBAC estricto) Disparador: El contador registra una factura de proveedor proveniente de una recepción de mercancía para programar su causación y pago. Precondiciones: 1. Recepción de mercancía registrada (CU-ERP-007).
2. Usuario autenticado con rol CONTADOR. Postcondiciones: Cuenta por pagar creada en estado PENDING o SCHEDULED con fecha de vencimiento calculada según plazos del proveedor. Resultado Exitoso: HTTP 201 Created con AccountsPayableDTO registrado y asientos contables generados.
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Gestiona el pasivo corriente derivado de las compras de inventario e insumos, controlando plazos y causación contable.

Frontera ERP y Aislamiento: Módulo financiero estrictamente interno. Desacoplado del E-Commerce público, registrando obligaciones frente a proveedores autorizados.

4. REGLAS DE NEGOCIO (RN)
  • RN-CXF-01 (Causación Obligatoria): Toda cuenta por pagar debe sustentarse en un acta de recepción válida (CU-ERP-007) y factura electrónica del proveedor.
  • RN-CXF-02 (Cálculo de Vencimiento): dueDate = receiptDate + paymentTermsDays definidos en el maestro del proveedor.
  • RN-CXF-03 (Control de Estado): Estados canónicos: PENDING, SCHEDULED, PAID, OVERDUE.
  • RN-CXF-04 (Default Deny): Acceso restringido exclusivamente a los roles CONTADOR y GERENTE_GENERAL.
  • RN-CXF-05 (SLO Rendimiento): Tiempo de procesamiento ≤ 250 ms (p95) en Google Cloud Run.
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Solicitud de Causación: El contador envía POST /api/v1/erp/accounts-payable con los datos de la factura, número de recepción y términos de pago.
  • 2 Validación de Acceso: El API Gateway y middleware RBAC verifican el token JWT y rol CONTADOR.
  • 3 Verificación de Recepción: Finance Service comprueba en Cloud SQL que la recepción de mercancía exista y esté pendiente de causación.
  • 4 Cálculo Financiero: Se calcula la fecha de vencimiento sumando los días de plazo del proveedor a la fecha de recepción.
  • 5 Persistencia Atómica: Se registra la obligación en erp_accounts_payable con estado inicial PENDING.
  • 6 Auditoría Estructurada: Se emite log estructurado JSON a Cloud Logging registrando la causación contable.
  • 7 Confirmación: El servicio responde HTTP 201 Created con AccountsPayableDTO y programación de tesorería.

8. FLUJOS ALTERNATIVOS / EXCEPCIONES
Código Situación Comportamiento del Sistema
FA-01 Recepción de mercancía inexistente HTTP 404 Not Found indicando que no hay acta de muelle para asociar la factura.
FA-02 Token ausente o rol no autorizado HTTP 403 Forbidden bajo la política Default Deny.
FA-03 Factura ya causadas previamente HTTP 409 Conflict por duplicidad de número de factura para el mismo proveedor.
FA-04 Monto de factura excede valor PO HTTP 422 Unprocessable Entity requiriendo nota de ajuste o auditoría contable.
FA-05 Fallo en Cloud SQL HTTP 500. Notificación en Cloud Logging y mensaje amigable de reintento.

  • Cabecera Cuenta por Pagar: id (AP-YYYYMM-XXXX), supplierId, goodsReceiptId, invoiceNumber.
  • Montos y Plazos: subtotal, tax, totalAmount, invoiceDate, dueDate, paymentTermsDays.
  • Estado Financiero: status (PENDING, SCHEDULED, PAID, OVERDUE).
  • Auditoría: createdBy, createdAt, updatedBy, updatedAt.
  • Moneda Operativa: COP ($ Pesos Colombianos).
