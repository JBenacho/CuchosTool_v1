CU-SEC-011 - Gestionar secretos mediante Secret Manager

Proyecto: CuchosTool.com | Baseline: SRS v5.0 / ARQ v6.0 / BL v5.0
Módulo: Seguridad / IAM / DOM-SEC | Fecha: 02/09/2026
Responsable: Nicola | Rol: Arquitecto & Dirección Técnica
1. Información General
ID / Código: CU-SEC-011
Trazabilidad: RS-002, RNF-005, BL-019, BR-02
Nombre: Gestionar secretos mediante Secret Manager
Objetivo: Aprovisionar, rotar y acceder de manera segura a secretos criptográficos y credenciales en Google Secret Manager bajo IAM estricto.
Actor Principal: ADMINISTRADOR / Service Account
Actores Sec.: BFF Router, Secret Manager Svc, GCP SM, Pub/Sub
Tipo / Prioridad: Infraestructura Esencial
Estado: Aprobado / Gestión de Secretos
Disparador: Petición administrativa HTTP POST/PUT /api/v1/seguridad/secretos.
Precondiciones: 1. JWT activo con rol administrador o SA autorizada.
Resultado: HTTP 201 Created + SecretMetadataDTO.
2. Diagrama de Casos de Uso (UML)
3. Descripción y Alcance

Propósito: Custodiar, versionar y rotar material criptográfico en Google Secret Manager.

Acceso: Administrador o Service Account bajo Default Deny.

Frontera ERP: Seguridad e infraestructura; suministra llaves y credenciales cifradas.

4. Reglas de Negocio (RN)
  • BR-02 / RN-SEC-001: IAM de mínimo privilegio con Default Deny.
  • RN-SEC-011 / RNF-005: Cero secretos en texto plano en logs o repositorios.
  • RF-SEC-008 / RN-SEC-007: Auditoría forense obligatoria (Acción Tipo E) en Pub/Sub.
  • RN-OPS-012: Latencia p99 ≤ TBD ms.
5. Flujo Principal (Camino Feliz)
1
Administrador o proceso invoca POST /api/v1/seguridad/secretos.
2
Gateway valida token JWT e inyecta X-Correlation-ID.
3
Identity Service comprueba permiso IAM:SECRET:MANAGE.
4
Microservicio invoca API de Google Secret Manager vía Service Account.
5
Se añade nueva versión cifrada del payload secreto.
6
Publicación de evento inmutable SecretVersionCreated a Pub/Sub.
7
Retorno de HTTP 201 Created con SecretMetadataDTO.
