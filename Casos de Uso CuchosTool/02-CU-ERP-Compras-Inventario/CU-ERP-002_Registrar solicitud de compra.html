1. INFORMACIÓN GENERAL
ID / Código: CU-ERP-002 [Trazabilidad: RF-CO-001, US-114, BR-02, BR-03][cite: 2] Nombre: Registrar solicitud de compra Objetivo: Registrar formalmente una solicitud interna de compra (PR) de ítems, insumos o herramientas requeridas por áreas operativas, validando justificación y partidas[cite: 2]. Actor Principal: EMPLEADO / OPERATIVO (Autenticado / JWT interno) Actores Sec.: COMPRAS (ACT-09), Cloud SQL PostgreSQL, Cloud Logging[cite: 2] Tipo / Prioridad: Transaccional Interno Prioridad Alta / Esencial Estado / Alcance: Aprobado / ERP Backoffice (Pre-orden de abastecimiento interno bajo RBAC)[cite: 1] Disparador: El colaborador o líder de área crea un requerimiento de compra para reposición o insumos operativos. Precondiciones: 1. Usuario interno autenticado con rol operativo o administrativo.
2. Ítems o referencias registrados en el catálogo maestro o insumos. Postcondiciones: Solicitud de compra creada con estado PENDING_REVIEW e historial de trazabilidad en base de datos. Resultado Exitoso: HTTP 201 Created con PurchaseRequisitionDTO y consecutivo oficial asignado (PR-YYYYMM-XXXX).
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Permite levantar requerimientos de insumos o reposición de existencias antes de cotizar o emitir una orden de compra vinculante[cite: 2].

Frontera ERP y Aislamiento: Las solicitudes son documentos de intención interna que no generan reservas de inventario ni cuentas por pagar contables. El E-Commerce público no tiene visibilidad de este ciclo de abastecimiento[cite: 1, 2].

4. REGLAS DE NEGOCIO (RN)
  • RN-REQ-01 (Mínimo de Líneas): Toda solicitud de compra debe incluir al menos un (1) ítem con cantidad entera positiva (> 0).
  • RN-REQ-02 (Justificación Obligatoria): Se exige campo de motivo o justificación técnica de la compra para trazabilidad de auditoría.
  • RN-REQ-03 (Estado Inicial Inmutable): Toda solicitud nace en estado PENDING_REVIEW.
  • RN-REQ-04 (Imputación por Área): Debe vincularse al centro de costos o departamento del solicitante.
  • RN-REQ-05 (SLO Rendimiento): Tiempo de procesamiento y respuesta ≤ 250 ms (p95) en Google Cloud Run[cite: 3].
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Captura de Requerimiento: El solicitante ingresa la justificación, departamento y lista de ítems emitiendo POST /api/v1/erp/purchase-requisitions[cite: 2].
  • 2 Validación de Acceso: El API Gateway comprueba el token JWT del colaborador interno bajo la política de control de acceso RBAC[cite: 1, 2].
  • 3 Comprobación de Datos: Requisition Service valida que existan líneas con cantidades válidas y justificación no vacía[cite: 2].
  • 4 Asignación de Consecutivo: Se genera el identificador único correlativo PR-YYYYMM-XXXX.
  • 5 Persistencia Atómica: Se almacena la cabecera en erp_purchase_requisitions y el detalle en erp_requisition_items dentro de Cloud SQL.
  • 6 Auditoría Estructurada: Se emite log estructurado JSON a Cloud Logging con UserId, PRId y Centro de Costos[cite: 7].
  • 7 Confirmación: El servicio responde HTTP 201 Created con PurchaseRequisitionDTO para revisión por parte de Compras[cite: 2].

  • Trazabilidad: createdAt, createdBy, approvedBy, approvedAt[cite: 7].
