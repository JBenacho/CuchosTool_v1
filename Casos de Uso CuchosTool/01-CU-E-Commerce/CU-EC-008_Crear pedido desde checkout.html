1. INFORMACIÓN GENERAL
ID / Código: CU-EC-008 [Trazabilidad: RF-EC-004, RF-CORE-002, BL-023, US-008] Nombre: Crear pedido desde checkout Objetivo: Formalizar la pre-orden de compra, ejecutar la reserva atómica de inventario en BD y emitir el evento asíncrono a Cloud Pub/Sub en estado PENDING_PAYMENT. Actor Principal: Cliente E-Commerce (Autenticado / JWT obligatorio) Actores Sec.: Checkout Service (DOM-05), Inventory Service (DOM-04), Cloud SQL, Cloud Pub/Sub Tipo / Prioridad: Transaccional Crítico Prioridad Alta / Esencial Estado / Alcance: Aprobado / E-Commerce Transaccional (Reserva atómica BL-023) Disparador: El cliente valida dirección de entrega, método de pago y pulsa "Confirmar pedido / Proceder al pago". Precondiciones: 1. Sesión autenticada con JWT vigente.
2. Carrito activo con ítems e inventario neto disponible suficiente. Postcondiciones: Pedido persistido (PENDING_PAYMENT), stock reservado (quantityReserved += qty) y evento emitido a Pub/Sub. Resultado Exitoso: HTTP 201 Created con OrderDTO y referencia comercial para pago (CU-EC-010).
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Punto de inflexión transaccional donde el carrito se convierte en un compromiso de compra vinculante y se bloquea inventario.

Frontera ERP y Aislamiento: La orden se crea en PENDING_PAYMENT sin generar aún factura DIAN ni orden de despacho logística. El ERP solo será notificado tras la confirmación del pago.

4. REGLAS DE NEGOCIO (RN)
  • RN-CHK-01 (BL-023): Reserva atómica con bloqueo transaccional. Si netAvailable < qty, rollback y 409 Conflict.
  • RN-CHK-02: Autenticación obligatoria con JWT (Default Deny); no se permiten órdenes anónimas.
  • RN-CHK-03: Totalización en COP: total = subtotal + tax (19%) + shippingCost.
  • RN-CHK-04: Publicación obligatoria de evento order.created con TraceId/CorrelationId a Cloud Pub/Sub.
  • RN-CHK-05: SLO de rendimiento: latencia transaccional p99 ≤ 800 ms en Cloud Run.
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Confirmación de Checkout: El cliente autenticado envía POST /orders con cabecera Bearer Token, dirección de envío y sessionId.
  • 2 Apertura de Transacción ACID: Checkout Service inicia transacción serializable en Cloud SQL PostgreSQL.
  • 3 Reserva Atómica de Inventario: Se ejecuta bloqueo de stock neto y se incrementa quantity_reserved += item.qty para cada ítem (BL-023).
  • 4 Persistencia del Pedido: Se inserta el registro en orders (status: "PENDING_PAYMENT") y sus líneas de detalle en order_items.
  • 5 Commit y Limpieza: Se confirma la transacción en base de datos y se vacía el carrito del cliente de forma idempotente.
  • 6 Publicación de Evento Asíncrono: Se publica el mensaje order.created en el tópico de Google Cloud Pub/Sub con CorrelationId.
  • 7 Respuesta al Frontend: Se retorna HTTP 201 Created con OrderDTO y referencia para redirección a la pasarela de pagos.

8. FLUJOS ALTERNATIVOS / EXCEPCIONES
Código Situación Comportamiento del Sistema
FA-01 Stock insuficiente al checkout HTTP 409 Conflict. Rollback transaccional inmediato sin alterar existencias ni emitir eventos.
FA-02 Token ausente o caducado HTTP 401 Unauthorized. Redirección forzada al Login preservando el carrito.
FA-03 Fallo en Cloud SQL (Deadlock) HTTP 500 Internal Error. Reintento automático interno (hasta 3 veces) antes de notificar fallo.
FA-04 Fallo en Cloud Pub/Sub El pedido se conserva en BD y se almacena en tabla Outbox para reintento asíncrono con DLQ.
FA-05 Carrito vacío o inexistente HTTP 400 Bad Request. Bloquea la creación del pedido y redirige al catálogo general.
9. DATOS UTILIZADOS
  • Entidad Order: id (ORD-YYYYMMDD-XXXX), customerId, status, subtotal, tax, totalAmount.
  • Entidad OrderItem: orderId, productId, quantity, unitPrice.

  • Evento order.created: eventId, orderId, traceId, timestamp.
  • Moneda Oficial: COP ($ Pesos Colombianos).

  • ✓ Autenticación obligatoria con JWT (Default Deny aplicado).
  • ✓ Estado inicial inmutable: PENDING_PAYMENT.
  • ✓ Publicación de evento order.created a Cloud Pub/Sub.
  • ✓ Latencia de respuesta transaccional: p99 ≤ 800 ms.
  • ✓ Desacoplamiento: cero llamadas síncronas al ERP contable/DIAN.
