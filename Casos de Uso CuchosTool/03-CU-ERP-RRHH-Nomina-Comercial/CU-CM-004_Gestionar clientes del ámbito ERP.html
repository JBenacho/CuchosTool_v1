Actor Principal: ADMINISTRADOR_COMERCIAL / VENDEDOR (Autenticado / JWT interno) Actores Sec.: Commercial Service (DOM-CM-01), Cloud SQL PostgreSQL, Cloud Logging Tipo / Prioridad: Transaccional ERP / Maestro Prioridad Alta / Esencial Estado / Alcance: Aprobado / Backoffice ERP (Control de cartera y clientes corporativos bajo RBAC) Disparador: El administrador comercial o vendedor registra un nuevo cliente corporativo o actualiza su línea de crédito. 2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Administra el directorio y control de cartera de clientes B2B dentro del ERP comercial.

Frontera ERP y Aislamiento: Módulo comercial interno. Estrictamente separado de la base de usuarios del E-Commerce público.

4. REGLAS DE NEGOCIO (RN)
  • RN-CM-01 (NIT / RUT Único): El número de identificación tributaria (NIT) o documento del cliente ERP debe ser único en la tabla erp_clients.
  • RN-CM-02 (Límite de Crédito): Todo cupo de crédito asignado debe expresarse en COP y contar con aprobación gerencial si supera los umbrales establecidos.
  • RN-CM-03 (Restricción de Baja): No se puede eliminar un cliente que mantenga facturas pendientes de cobro o cartera vencida.
  • RN-CM-04 (Default Deny): Acceso restringido exclusivamente a roles comerciales autorizados (ADMINISTRADOR_COMERCIAL, VENDEDOR).
  • RN-CM-05 (SLO Rendimiento): Tiempo de procesamiento ≤ 250 ms (p95) en Google Cloud Run.
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Captura de Datos: El usuario comercial envía POST /api/v1/erp/commercial/clients indicando razón social, NIT, límite de crédito, plazos y vendedor asignado.
  • 2 Validación de Acceso: El API Gateway y middleware RBAC verifican el token JWT corporativo y los permisos del rol.
  • 3 Verificación de Unicidad: Commercial Service comprueba en Cloud SQL que el NIT no exista previamente en el ERP.
  • 4 Persistencia Atómica: Se registra el cliente corporativo en la tabla erp_clients con estado ACTIVE.
  • 5 Auditoría Estructurada: Se emite log estructurado JSON a Cloud Logging registrando la creación del cliente B2B.
  • 6 Confirmación: El servicio responde HTTP 201 Created con ErpClientDTO estructurado.
  • 7 Habilitación Operativa: El cliente queda disponible para la emisión de cotizaciones, órdenes de venta y facturación ERP (CU-CM-007).

8. FLUJOS ALTERNATIVOS / EXCEPCIONES
Código Situación Comportamiento del Sistema
FA-01 NIT o documento duplicado HTTP 409 Conflict indicando que ya existe un cliente corporativo registrado con el mismo NIT.
FA-02 Token ausente o rol no autorizado HTTP 403 Forbidden bajo la política de seguridad Default Deny.
FA-03 Límite de crédito negativo HTTP 400 Bad Request por valor de crédito inválido en COP.
FA-04 Intento de eliminar cliente con cartera pendiente HTTP 422 Unprocessable Entity impidiendo la baja del cliente si mantiene facturas abiertas.
FA-05 Fallo en Cloud SQL HTTP 500. Notificación en Cloud Logging y mensaje amigable de reintento.
