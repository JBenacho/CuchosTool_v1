1. INFORMACIÓN GENERAL
ID / Código: CU-EC-004 [Trazabilidad: RF-EC-001, RF-EC-003, BL-033, US-004] Nombre: Consultar ficha de producto Objetivo: Proveer información técnica exhaustiva (dimensiones, voltaje, garantía comercial, marca, fotos HD y precio base en COP) de un artículo específico. Actor Principal: Cliente E-Commerce / Visitante (Público) Actores Sec.: Product Service (DOM-01), Cloud CDN / Storage, Cloud SQL Tipo / Prioridad: Consulta Pública Prioridad Alta / Esencial Estado / Alcance: Aprobado / E-Commerce Abierto (Sin token JWT ni sesión obligatoria) Disparador: El visitante pulsa sobre un artículo del catálogo o ingresa mediante URL canónica (/products/:id). Precondiciones: 1. Microservicios activos en Cloud Run.
2. El producto existe y está publicado como activo (isActive = true). Postcondiciones: N/A (Operación idempotente de solo lectura; no altera BD ni reserva existencias). Resultado Exitoso: HTTP 200 OK con payload DTO completo, galería multimedia y precio base en COP.
2. DIAGRAMA DE CASOS DE USO (UML)
3. DESCRIPCIÓN Y ALCANCE

Permite la inspección detallada de herramientas para la toma de decisión de compra con diseño responsivo y optimización SEO.

Aislamiento de Persistencia: Consume exclusivamente el esquema catalog.products sin realizar llamadas directas a las tablas transaccionales del ERP.

4. REGLAS DE NEGOCIO (RN)
  • RN-EC-001 / BL-033: Consulta pública abierta; no exige token de autenticación.
  • RN-CAT-01: Solo se exponen ítems con isActive = true; de lo contrario retorna 404.
  • RN-CAT-03: Precios base oficiales en COP sin incluir costo de despacho.
  • RN-CAT-05: Latencia SLO: ≤ 100 ms (p95 CDN) y ≤ 250 ms en Cloud Run.
  • RN-CAT-07: Estructura técnica estandarizada (marca, potencia, voltaje, peso, garantía).
5. FLUJO PRINCIPAL (CAMINO FELIZ)
  • 1 Solicitud de Ficha: El usuario accede a la vista de detalle mediante URL canónica o clic en tarjeta emitiendo GET /products/:id.
  • 2 Enrutamiento Público: El BFF procesa la petición de forma abierta sin exigir cabecera Authorization (cumpliendo BL-033).
  • 3 Consulta en Persistencia: Product Service consulta en Cloud SQL PostgreSQL buscando el producto por clave primaria y validando isActive = true.
  • 4 Resolución Multimedia: Se obtienen y mapean las URLs absolutas de la galería fotográfica HD cacheadas en Cloud CDN.
  • 5 Ensamblado del DTO: Se consolida el payload con ficha técnica, atributos, marca, garantía y precio base en Pesos Colombianos (COP).
  • 6 Métricas en Observabilidad: Se emite registro estructurado JSON a Cloud Logging con métricas de duración y SKU.
  • 7 Presentación en UI: El frontend renderiza la ficha técnica completa con galería de imágenes, ficha descargable y botón de compra.

9. DATOS UTILIZADOS
  • Claves de Consulta: id (PROD-XXXX), sku, slug.
  • Datos Comerciales: name, description, brand, category, basePrice, currency ("COP"), isActive.
  • Especificaciones Técnicas: attributes (voltaje, potencia, dimensiones, peso, uso industrial).
  • Garantía: warrantyMonths, policyDocumentUrl.
  • Galería Multimedia: images[] (mainUrl, galleryUrls, thumbnail).
10. CRITERIOS DE ACEPTACIÓN (DOD)
  • ✓ Acceso 100% público garantizado sin token de autenticación (BL-033)[cite: 2].
  • ✓ Filtro estricto por isActive = true; 404 para inactivos[cite: 2].
  • ✓ Aislamiento total de las bases de datos transaccionales del ERP.
  • ✓ Carga fluida de assets desde Cloud CDN (≤ 100 ms p95).
  • ✓ Latencia de respuesta backend: ≤ 250 ms en Cloud Run.
  • ✓ Emisión de logs estructurados JSON a Google Cloud Logging[cite: 2].
